# AGENTS.md

## Repository layout

- The workspace root **is** the git repository (remote `github.com/tommasocretu/AR_Camera`, branch `main`); run all git commands from there. Don't create nested repositories.
- The Godot project is `ar-camera_godot/` (project name `ARCamera`).
- Native code: `thirdparty/godot_arcore/` (vendored ARCore GDExtension plugin) and `native/marker_ar/` (own Android plugin, Kotlin + OpenCV). Both are built by the scripts in `tools/` and installed into `ar-camera_godot/addons/` (gitignored).
- `.gitignore` at the repo root is the effective ignore file for the whole tree; `ar-camera_godot/.gitignore` only adds `/android/`.

## Running Godot

Godot is installed only as a Flatpak (`org.godotengine.Godot`, 4.7.2) — there is no `godot` binary on `PATH`. Invoke it through Flatpak:

- Open editor: `flatpak run org.godotengine.Godot --path ar-camera_godot`
- Headless asset reimport after adding files: `flatpak run org.godotengine.Godot --headless --path ar-camera_godot --import`
- Headless editor startup check: `flatpak run org.godotengine.Godot --headless -e --path ar-camera_godot --quit`

`-e` (editor mode) is the safest check for scripts, autoloads and editor plugins; it is required for import/validation.

## Android build

- `tools/build_arcore.sh [--gradle]` — builds the vendored ARCore plugin and fills `ar-camera_godot/addons/ARCorePlugin/`.
- `tools/build_marker_ar.sh` — builds the marker plugin (Gradle only, no NDK) and fills `ar-camera_godot/addons/MarkerARPlugin/`.
- `tools/export_android.sh` — exports the debug APK (requires both addons).
- `tools/generate_aruco_marker.py` — regenerates the printable marker in `ar-camera_godot/assets/markers/` (requires `opencv-python`).

Requirements: Android SDK in `$HOME/Android/Sdk` (`platforms;android-33`, `build-tools;33.0.2`, and `ndk;23.2.8568313` for ARCore), JDK 17 in `$HOME/.local/opt/temurin-17`, python3 for `tools/.venv`. The marker plugin pulls OpenCV from Maven Central (`org.opencv:opencv:4.12.0`) via Gradle; the AAR is injected into the app APK by the plugin's export script.

## Vendored patches

- `thirdparty/godot_arcore`: local patches are documented in `thirdparty/README.md` (GDScript interface, raycast fixes, Gradle wrapper, plus the marker-backend patches: `getArCoreAvailability`, opt-in install prompt, manifest `optional`).
- `native/marker_ar`: own code (not vendored); frame transforms are adapted from godot-native-camera (MIT), see `native/README.md`.

## Project constraints

- `project.godot` pins Godot 4.7, the **Mobile** renderer, Jolt physics, and `rendering_device/driver.windows="d3d12"`. This is a mobile AR target: keep it mobile-compatible, don't switch to Forward+ or add desktop-only APIs.
- On Android the renderer is forced to `gl_compatibility` (`renderer/rendering_method.mobile`); on desktop it stays Mobile.
- `.godot/` is generated editor cache (gitignored) — never edit or commit it. `*.import` files are generated by the editor; don't hand-edit them.
- `.gitattributes` normalizes all text files to LF.

## Current state

- AR app built on the `ARSession` facade; the backend is selected at runtime:
  - ARCore when "Google Play Services for AR" is installed (certified devices);
  - ArUco marker (`MarkerARPlugin`, Kotlin + OpenCV) on any Android device without Google services;
  - simulated on desktop.
- "place cube" experience: reticle, ghost and tap-to-place; with the marker backend cubes are anchored to the marker.
- README and project docs are in Italian.
- When adding GDScript, follow the official Godot 4 style (tab indentation, `snake_case` file names).
